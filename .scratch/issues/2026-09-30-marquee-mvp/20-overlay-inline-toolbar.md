# 20: 覆盖层内的浮动工具栏（骨架）

**What to build:** 框选之后**不再打开独立编辑器窗口** —— 在选区**下方**浮出一排简洁工具栏，
就地完成「完成 / 复制 / 保存 / 取消」。本票**只做工具栏与收尾动作**，标注绘制留给 21。

**Blocked by:** 无（覆盖层的键盘与窗口呈现已在 `d107ee7` 修好）

**Status:** 🟡 已实现（2026-10-01），待人工验收

## 为什么改

用户原话：

> 不在用户按回车键后进行编辑，而是框选之后在框选区域下呈现一个简洁的工具栏，不阻断用户操作。

现状的问题不是"少了编辑器"，而是**流程被切成两段**：
拖完选区 → 按 `⏎` → 屏幕上正在看的选区整个消失 → 弹出另一个窗口。
用户失去空间感（"我刚才框的是哪儿"），还平白多一次窗口切换。

## 设计约束（已定）

- 工具栏**贴在选区下方**；下方空间不够（选区贴近屏幕底边）则翻到**上方**。
  翻转判断与现有读数框（`SelectionOverlayView.drawReadout`）同源，直接沿用它的做法。
- **不遮选区**：与选区边缘留间距，绝不覆盖选区内任何像素。
- **拖拽过程中不显示**：只在落点之后（`SelectionSession.isSettled`）出现。
  拖到一半工具条跟着晃，既干扰又没意义。
- **不阻断**：工具栏只是覆盖层上多画的一层；点它之前，用户看到的就是最终成品。
- **`⏎` 的语义从「打开编辑器」改为「完成」**（栅格化 + 写剪贴板 + 关闭覆盖层）。
  ⚠️ 这会改掉一批既有验收项（`STATUS-AND-ACCEPTANCE.md` 里多处「⏎ 确认」），文档要同步。

## 本票只做动作，不做工具

第一版工具栏只有动作：**完成 / 复制 / 保存 / 取消**。

理由是刻意的：**标注绘制是另一条独立链路**（事件 → 会话 → 绘制 → 导出）。
把它和"工具栏出现在哪、不遮不遮"混在一张票里，一旦出问题就没法区分是**布局错了**还是**绘制错了**
—— 而这两类的排查手段完全不同。先把布局与收尾钉死，再打穿绘制。

## Acceptance criteria

> 下面标 `[x]` 的是**代码层面已完成**；真机行为仍需人工过一遍（清单见 §人工验收）。

- [x] 拖出选区松开 → 选区下方出现工具栏；**拖拽过程中不出现**（`toolbarFrameIfSettled` 里 `guard session.isSettled`）
- [x] 选区贴到屏幕底边时工具栏翻到上方，且**始终完整可见**（Core 单测覆盖：翻面 + 夹取）
- [x] 工具栏不遮挡选区内的任何像素（单测 `neverCoversSelection` 用 5 种贴边选区断言不相交）
- [x] `⏎` / 「完成」→ 图进剪贴板 + 覆盖层关闭，**不再打开任何窗口**（`Outcome.completed(_:openEditor:)` 传 `false`）
- [x] `Esc` / 「取消」→ 覆盖层关闭，剪贴板内容不变（复用原有 `cancel()`）
- [x] 窗口模式与整屏模式同样出工具栏（在 `refresh()` 里**统一挂一次**，不在各分支里各挂一遍）
- [x] **长截图不受影响** —— `finishScrollCapture` 显式传 `openEditor: true`
- [x] 位置计算是 Core 纯函数 + 单测（`OverlayToolbarTests`：11 条，含贴边 / 翻面 / 副屏 / 极小屏 / 命中测试）

## 实现记录（2026-10-01）

### 代码落点

| 关注点 | 落在哪 |
| --- | --- |
| 位置计算 + 按钮几何 | `MarqueeCore.OverlayToolbar`（纯函数，11 条单测） |
| 绘制 | `SelectionOverlayView.drawToolbar`（AppKit，与命中测试**共用同一份几何**） |
| 命中拦截 | `SelectionOverlayView.mouseDown` —— 点在工具栏上就**不进入拖拽** |
| 动作 | `SelectionOverlayController.perform(toolbarButton:)` |
| 「要不要开编辑器」 | `Outcome.completed(_:openEditor:)` |

### 几个刻意的决定

1. **绘制与命中用同一份几何。** 按钮位置一律走 `OverlayToolbar.hitFrame`，
   视图不自己算。各算各的会偏出去几个点，而那种偏差的表现是
   "按钮看着在这儿、点它没反应"，很难联想到是布局算错。
2. **工具栏在 `refresh()` 里统一挂一次**，而不是塞进"区域落点 / 窗口落点"每个分支 ——
   那样以后加第三种落点方式时一定会漏掉一处。
3. **`openEditor` 是显式的关联值**，不是 controller 上的隐式状态。
   改了枚举之后编译器会把 6 个调用点全列出来，一处都漏不掉。
4. **`mouseDown` 里拦工具栏，而不是在 delegate 里拦。**
   否则用户在按钮上按下再挪一下，就会把刚框好的选区改掉。

### 一个当场抓到的小错

写完就发现：工具条宽度按"间距在中间"算（`groupingGap` 在两组之间），
而按钮偏移按"间距在末尾"算 —— 差 4 点，最后一个按钮会探出右边一点。
两条规则各自都对，凑在一起才错。补了 `buttonsFitInsideToolbar` 钉住它。

### 验证

298 测试全绿（新增 11 条）。变异测试注入 1 处（去掉"放不下就翻到上方"）
→ **3 条断言变红**，确认不是空跑。App 层 typecheck 退出码 0。

# 16: 最近截图面板

**What to build:** 菜单栏里能直接看到最近截的几张图，缩略图列表，点一下就能复制或重新编辑。解决"刚截的图找不到了"这件事，但**不做完整图库窗口**——只做菜单栏里的一层面板，避免范围蔓延。

**Blocked by:** 05

**Status:** 🟡 已实现，待人工验收（2026-10-01）

## 实现记录

### 落点

| 部分 | 在哪 |
| --- | --- |
| 条目模型 + 磁盘仓库 + 淘汰/删除 | `MarqueeHistory.CaptureHistoryStore`（12 条单测） |
| 记录接缝 `CaptureHistoryWriting` | **`MarqueeCore`**（见下） |
| 记录动作 | `CaptureOutput.finish`（剪贴板写完之后） |
| 面板 | `App/RecentCapturesPanelController`（菜单栏弹层） |
| 装配 | `CaptureCoordinator` |

### 接缝为什么在 Core

`CaptureOutput` 在 Core、仓库要碰文件系统 —— 协议只能落在 Core，
否则形成 `Core → History → Core` 的循环。与 `ClipboardWriting` / `ScreenCapturing`
同一套做法（PITFALLS 86）。

### 存在磁盘上的三样东西

```
~/Library/Application Support/Marquee/history/
  index.json                      条目清单（新→旧）
  <uuid>-original.png             原图（**未拍平**）
  <uuid>-annotations.json         标注向量（没有标注就不写）
```

**原图 + 标注分开存**，而不是只存拍平后的成品 —— 否则「重新编辑」就退化成
"在已经画好的图上再画"：原有的标注成了像素的一部分，既不能选中也不能撤掉。

### 几处刻意的决定

- **"点击复制"是重新栅格化一遍**（原图 + 标注），不存拍平副本：
  磁盘上少一份冗余，而且走的是**导出那条完全相同的代码路径** ——
  于是"从历史复制出来的"与"当时按 ⏎ 得到的"在结构上就是同一张图。
- **没有标注时复用刚编码好的 PNG**：那是最常见的情况（拍平后的图就是原图），
  重新编码一张 2560×1600 要几十毫秒，而每一毫秒都在"按下快捷键 → 能粘贴"的预算里。
- **历史记在剪贴板之后**：用户"能粘贴"的那一刻不该等它。
- **淘汰顺序只由数组顺序决定**，不按时间重排 —— 万一系统时钟被改过，
  按时间排会把"刚截的"排到最旧、然后删掉。
- **只删自己写出来的文件**（按条目里记的文件名删），用户自己另存的东西永远不在删除范围内。
- **每行的动作携带条目的 `id`**，不是行号 —— 列表在点下去之前就可能重建过（PITFALLS 87）。
- **缩略图用 `CGImageSourceCreateThumbnailAtIndex`**，不"先加载整图再缩"
  —— 12 张 5K 图那样做要几百 MB，面板一打开就卡住（PITFALLS 88）。
- **上限 20 条 / 面板最多列 12 条。**

### 未做

- 历史里没有"导出这一张到…"（可以从编辑器保存）
- 没有搜索 / 分组 / 按日期归档 —— 那是一个图库，不是这一票的范围

## Acceptance criteria

## 设计约束（已定）

- **菜单栏内一层面板**即可，不新增独立图库窗口（范围约束）
- 保留原始图 + 标注向量，支持无损重新编辑（不是只存栅格化结果）
- 有数量上限与自动清理，不能让磁盘无限增长

## Acceptance criteria

- [x] 菜单栏可展开最近截图面板，显示最近若干张的缩略图（菜单「最近截图」→ 弹层，最多 12 条）
- [x] 点击缩略图可复制到剪贴板（**重新栅格化**，与当时按 ⏎ 得到的一致）
- [x] 可从面板重新进入编辑器，且**原有标注仍可编辑**（存的是原图 + 标注向量）
- [x] 可删除单条记录，删除后磁盘上的对应文件也被清理
- [x] 超过上限时自动清理最旧的，且**不会误删用户自己保存到别处的文件**（有测试）
- [ ] 面板打开速度实测记录（缩略图按需解码，逻辑上不会卡；实测值待人工填）
- [x] 持久化与清理策略有单元测试（12 条：上限、清理顺序、删除后的文件系统状态、坏索引降级）

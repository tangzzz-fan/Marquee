## 二、马赛克 / 模糊 —— ✅ 已完成

**难点是底图从哪来。** 覆盖层刻意不铺整屏截图（PRD 5.5）：它只是一层变暗蒙层 + 挖洞，
屏幕内容是**穿透看到的真东西**，不在我们手里。而打码必须拿到那块像素才能算。

**解法：复用放大镜那套冻结帧。** `LensFrameProviding` 在覆盖层出现时已经取过一屏像素
（见 `MagnifierSeams.swift`），**不额外采一次屏** —— 也就不会因为"再采一次"
而把覆盖层自己拍进去。

### 关键决定：预览的底图与导出**共用同一套布局**

`OverlayRedactionSource` 不是"从选区所在那屏裁一块"，而是复用
`SelectionLayout` + `ImageCompositing` —— 与导出**完全相同**的布局规则
（逐屏取交集、输出倍率取参与屏里最大的那个）。

自己裁一块在单屏下看不出差别，跨屏时尺寸与对齐都会跟导出不一样 ——
而马赛克看起来"差不多"，这种不一致极难发现。

### 关键决定：`sourceScale`（底图每点多少像素）

标注坐标是**点**，底图是**像素**。`AnnotationDrawing.draw(..., sourceScale:)` 就是这个倍率，
它同时作用于两处：
- 裁底图时的像素矩形（`frame × scale`）
- **传给滤镜的强度**（`effectStrength × scale`，因为滤镜按底图像素工作）

漏掉第二处的话，2x 屏上预览的格子会**小一半** —— 而"格子小了点"只会被当成强度没调对。
有一条**逐像素**的回归盯着它（见 Acceptance criteria 最后一条）。

### 关键决定：三档尺寸按工具换意义

工具条的三个尺寸档在"画图形"时是线宽、在"画打码"时是打码强度
（与编辑器同一套做法）。**不新增控件** —— 工具栏每多一格就更宽，
而它有一条"必须放得进 1024 点的屏"的硬约束（现在 652 点）。
打码强度另立一组值（`AnnotationPalette.overlayRedactionStrengths = [4, 8, 16]`**点**）：
编辑器那三档的单位是**原图像素**，直接复用会在 2x 屏上差一倍。

### 拿不到底图时怎么办

缺任何一块屏的冻结帧 → **整体放弃**底图（`nil`），不给残缺的图
（缺的那块会显示成原图，看着像"打码没生效"，而用户可能就这么发出去了）。
此时预览不画打码，但**导出仍会应用**（底图从真实采集里来）——
所以落点后的提示行会说一句「⚠️ 打码预览不可用（没拿到屏幕像素）—— 标记仍然会写进成品图」。
不说的话，用户会看到"导出图里凭空多了一块打码"。

## 零、覆盖层里的输入框（本票的**共同前提**）

ticket 19 的「点尺寸数字输入精确尺寸」并到这里 —— 它和文字工具卡在同一件事上，
一个前提、两处用途，不该各做一半。

覆盖层是 `.nonactivatingPanel` 且层级很高（`.screenSaver`），
**`NSTextField` 在这个环境里能不能收键盘没有验证过** ——
而键盘恰恰是这个项目踩过坑的地方（PITFALLS 56：`⏎` 曾经完全收不到）。

**先做最小验证再决定形态**（不要靠猜）：

1. 在覆盖层上放一个 `NSTextField`，看能否聚焦、输入、走输入法打中文、`⏎` 提交。
2. 若不可行 → 用一个普通层级的 `NSPanel` 承载输入条，或在覆盖层里自绘输入框
   并自己收 `keyDown`（代价是中文输入法要自己处理，那很贵）。

⚠️ 还有一条：控制层的**本地键盘监听**会先吃掉所有按键（`handleOverlayKeyDown`）。
一旦有输入框在编辑，必须**整条让行**，否则用户敲的字全被当快捷键吞掉、
而且看起来像"输入框坏了"。

## 一、文字 —— ✅ 已完成

工具条上加了「文字」（T 图标，与编辑器同一个 SF Symbol），顺序也和编辑器一致：
`选择 矩形 椭圆 箭头 画笔 文字 马赛克 模糊`。

### 交互

- **点一下**放下输入点（不是拖一笔 —— 见 `OverlayTool.isStrokeBased`）
- 就近挂一个白色输入框，`⏎` 结算、`Esc` 放弃
- **结算 ≠ 丢弃**：点工具条 / 点别处 / 按 `⏎` 都是"把内容落成标注"，
  只有 `Esc` 才丢。其中「改颜色 / 改尺寸 / 撤销重做」这几格**连结算都不做** ——
  用户想改的就是正在打的那一行
- 空内容一律丢弃（不留看不见的空文字）

### 输入期间键盘要**整条让行**（PITFALLS 76）

覆盖层的键盘统一走应用级本地监听，而本地监听在事件到达窗口**之前**就跑 ——
不让行的话用户敲的每个字都被当快捷键吞掉。现在只拦 `Esc`，其余全部放回给输入框。

### 输入框为什么**不跟标注字号走**

它是**控件**，不是所见即所得的预览：44 点的字号会做出一个 60 点高的白条糊在图上，
反而看不清输入了什么（编辑器那个输入框也是固定 13 点，同理）。真正的字号在提交后生效。

### 原始需求（保留）



`AnnotationDrawing` 已经支持，缺的只有输入框（见上）。

## 三、选中 / 移动 / 删除 —— ✅ 已完成（缩放未做）

工具条最左边加了 **「选择」工具**（`OverlayTool.select`）。做成**显式工具**而不是
「自带行为」，是为了消歧：不选工具时拖动是改**选区几何**（拖角 / 框内移动），
选了「选择」时拖动是挪**标注**。否则「按在框内」到底该挪谁只能靠猜。

- [x] 点选（`annotation(at:)` 从前往后找；判据走 `Annotation.contains` ——
      箭头与画笔按**到路径的距离**判，斜线包围盒里有大片空白）
- [x] 拖动移动整框（`Annotation.translated(by:)`：框与路径一起走）
- [x] `Delete` 删除选中
- [x] `⌘Z` / `⇧⌘Z`（顺带：覆盖层此前只有按钮，没有快捷键）
- [x] 拖控制点改大小（8 个点；`⇧` 锁比例；最小 8 点停住不翻转；`Esc` 退回按下前那一版）

### 缩放这一块的坑：复用 `SelectionGeometry` 要先过一层坐标适配

`SelectionGeometry` 是 ticket 19 那套（控制点、对边固定、最小尺寸停住、`⇧` 锁比例），
想直接复用它 —— 但它是按 **Cocoa 约定**写的：`.top` = **`maxY`**（y 向上），
而标注是"原点左上、y 向下"。直接喂进去，用户拖"上边"动的是**下边**，
而且不崩不报错、只在拖到极限或锁比例时才显得怪。
**修法：`SelectionGeometry.YDown.flip(rect/point)` 显式适配，进去翻一次、出来翻一次**
（翻转是对合的，不引入额外状态）。两处翻转各做过一次变异，共 8 条断言变红。
详见 `docs/PITFALLS.md` 79。

### 几个刻意的决定

1. **`isDrawing` ≠「选了工具」**。`.select` 也是工具但它不画东西 ——
   两者混在一个判据里的话，选「选择」之后「拖动 = 画一笔」仍然成立，
   于是用户想点选一个箭头，结果在旁边画了个新矩形。
2. **拖动的基准是「按下那一刻的完整快照」**，不是每帧累加。
   累加会带浮点误差，而且中途改选中集合时基准就错了（已挪过的会被再挪一次）。
3. **点一下不动不算一步改动**（不进撤销栈）—— 否则撤销键会莫名其妙地点不动。
4. **撤销/重做之后要收拾选中集合**：撤销可能把「刚画的」收走，
   而选中集合里会留一个已不存在的 id。这条**没有可见症状**（现有的 guard 恰好挡住了），
   所以按「断言不变量」来守 —— 见 `OverlayAnnotationSessionTests` 里那条用例的注释。
5. **选了任何工具（含「选择」）都不再显示选区控制点**：那时拖动属于工具的语义，
   摆着控制点会让人以为能拖角改大小。
6. **`Esc` 退出任何工具**，不只是「画标注」。少了这一档，选了「选择」再按 `Esc`
   会**直接取消整次截图**。

## 零、输入框 —— ✅ 已实测为真，直接用 `NSTextField`

覆盖层面板是 `.nonactivatingPanel` + `canBecomeKey = true` + `becomesKeyOnlyIfNeeded = false`，
**按文档它应当能成为 key window**（那正是文字输入的前提）。
但本项目有一条反证：**视图的 `keyDown` 曾经完全收不到 `⏎`**（PITFALLS 56）。
两者对不上，所以**没有猜 —— 加了一条探针**，用户跑一次覆盖层，日志给出：

```
覆盖层焦点：panel.isKeyWindow=true firstResponder=true app.isActive=true
```

`true`。于是用真的 `NSTextField` —— **中文输入法的候选窗、联想、光标全都白拿**
（自绘输入框的话这三样都得自己实现，是个无底洞）。
这条探针留在 `present()` 里了：它是"输入框还能不能用"的唯一前置条件。

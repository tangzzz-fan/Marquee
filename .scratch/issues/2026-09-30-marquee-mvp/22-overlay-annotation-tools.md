# 22: 覆盖层内补齐其余标注工具

**What to build:** 21 已经打穿链路并做了形状类四个工具（矩形 / 椭圆 / 箭头 / 画笔）。
本票补齐**剩下的三类**，并把"画完就不能改"补上。

**Blocked by:** 21 ✅

**Status:** ready-for-agent

---

## 一、文字（`text`）

`AnnotationDrawing` 已经支持，缺的是**输入**。

覆盖层是 `.nonactivatingPanel` 且层级很高（`.screenSaver`），
**`NSTextField` 在这个环境里能不能收键盘没有验证过** ——
而键盘恰恰是这个项目踩过坑的地方（PITFALLS 56：`⏎` 曾经完全收不到）。

**先做最小验证再决定形态**（不要靠猜）：

1. 在覆盖层上放一个 `NSTextField`，看能否聚焦、输入、`⏎` 提交。
2. 若不可行 → 用一个普通层级的 `NSPanel` 承载输入条，或在覆盖层里自绘输入框
   并自己收 `keyDown`。

⚠️ 还有一条：控制层的**本地键盘监听**会先吃掉所有按键（`handleOverlayKeyDown`）。
一旦有输入框在编辑，必须**整条让行**，否则用户敲的字全被当快捷键吞掉、
而且看起来像"输入框坏了"。

## 二、马赛克 / 模糊（`mosaic` / `blur`）

`AnnotationDrawing.drawRedaction` 需要一个**与标注同坐标系的底图**。
覆盖层刻意不铺整屏截图（PRD 5.5），所以底图得另找来源：

- 放大镜那套 `LensFrameProviding` 已经会取**冻结的整屏像素**（覆盖层出现后取一屏），
  可以复用：把选区内那块裁出来，按"点 → 像素"倍率对齐给绘制用。
- ⚠️ 覆盖层与导出各算一次会**看起来差不多但不完全一样**（马赛克块对齐）。
  要对就都用同一份 `RedactionFilter`，且底图与标注的坐标系一致。

不在本票的话，`AnnotationDrawing` 传 `source: nil` 会**跳过**这两类 ——
所以绝不能在工具条上先摆两个按了没反应的按钮（这也是 21 只放四个工具的原因）。

## 三、选中 / 移动 / 删除（"画完还能改"）

现在只能靠撤销。要补：

- 点选一个标注（`AnnotationDocument.hitTest` 已有，含"箭头按到路径的距离判"的处理）
- 拖动移动整框（`Annotation.translated(by:)` 已有：框与路径一起走）
- 控制点改大小（`Annotation.applyFrame(_:)` 已有）
- `Delete` 删除选中

## Acceptance criteria

- [ ] 文字：在覆盖层里输入并落定，导出与所见一致
- [ ] 马赛克 / 模糊：块/模糊的对齐与导出**完全一致**
- [ ] 点选、拖动移动、控制点改大小、`Delete` 删除
- [ ] 撤销 / 重做覆盖以上全部
- [ ] 有输入框在编辑时，覆盖层的快捷键**让行**
- [ ] 工具栏不再 ≤ 9 个工具也**不必**扩到 9 个：序号仍是文字的预设，裁切见 19/23

## 风险

- 文字输入是本票唯一的未知项，**先验证再实现**。
- 打码的底图来源（冻结整屏）与选区的对齐是第二个未知项，同样先验后做。

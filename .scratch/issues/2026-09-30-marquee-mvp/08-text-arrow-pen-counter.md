# 08: 文字 / 箭头 / 画笔 / 序号标注

**What to build:** 在已有对象模型上补齐其余标注工具：文字（可直接输入与二次编辑）、箭头（指向性明确）、自由画笔、以及自动递增的序号标记。四种新标注与矩形一样，落地后都**可以被再次选中修改**。

序号标记不占独立工具位，收敛为文字工具的一个预设（`1.` `2.` 自增），以符合工具栏 ≤ 9 个工具的约束。

**Blocked by:** 07

**Status:** 已实现，待人工验收（2026-10-01）

## 实现要点

| 关注点 | 落点 |
| --- | --- |
| 箭头 / 画笔几何 | `MarqueeCore.AnnotationGeometry`（点到线段距离、箭头头部、路径包围盒、路径等比映射） |
| 文字测量与绘制 | `MarqueeCore.AnnotationText`（CoreText；**编辑器与导出共用**） |
| 对象模型 | `Annotation.path`（箭头 = 起点终点；画笔 = 折线点序列）、`Annotation.text`、`AnnotationStyle.fontSize` |
| 手势与序号 | `AnnotationEditorSession`（`.arrow` / `.pen` / `.text` 三个工具 + `TextPreset.counter`） |
| 画布 | `MarqueeEditor`：箭头（线 + 实心三角）、画笔（圆头圆角折线）、文字走 `withCGContext` |

### 为什么不把路径塞进 `AnnotationKind` 的关联值

那样 `kind` 就不再是简单的标签：命中测试、工具栏、序列化都要跟着解包。
"这个对象是什么"与"它的点在哪"本来就是两件事。

### 文字为什么必须两边共用一套 CoreText

编辑器（SwiftUI `Canvas`）与导出（`AnnotationRasterizer`）若各画各的，就会出现
"编辑器里刚好放得下、导出后被裁掉半个字" —— 而框的大小就是按测量结果算的。
所以两边都调 `AnnotationText.measure` / `.draw`，字体也只取一处（系统 UI 字体）。

**`Canvas.withCGContext` 的坐标系已实测**（`AnnotationTextCanvasTests`，用 `ImageRenderer`
把画布渲染出来读像素）：与 Core 的"左上原点、y 向下"一致，且 `clip` 之后仍能画。
这条不能靠猜 —— 猜反了就是**镜像文字**，而"有没有墨"这类断言看不出来。

### 序号为什么只是文字的预设

PRD 要求工具栏 ≤ 9 个工具，且序号标记在旧版里也不是独立能力。
所以它是文字工具的一个预设：内容直接是 `1.` `2.`…，可手动改起始值；
**只增不重排** —— 删掉 2 号不会让 3 号变成 2 号（重排会让用户已经说过的"第 3 点"错位）。

## 设计约束（已定）

- 四类新标注必须复用 07 建好的对象模型与撤销栈，不得各自造一套
- 序号标记是文字标注的一种预设，不新增工具按钮
- 文字以矢量方式保存（字符串 + 字体 + 字号 + 颜色），导出时才栅格化，保证可反复编辑
- 画笔用折线点序列保存，支持后续改色改粗细

- [x] 箭头指向与拖拽方向一致、线宽可调（头部尺寸跟着线宽走，有单测）
- [x] 画笔按间隔采点、框包住所有点（有单测）
- [x] 序号连续放置自动递增、可手动改起始值、**只增不重排**（有单测）
- [x] 四类新标注均可被选中、移动、删除、改色（移动时**路径跟着走**有单测）
- [x] `⌘Z` 对每一类的创建与修改都正确撤销（有单测）
- [x] 文字的几何与样式序列化一致：存 → 取 → 栅格化，像素级相等（有单测）
- [x] 导出后渲染正确：箭头头部、画笔笔画、文字基线（`rasterizerDrawsEveryKind`）
- [x] **文字不镜像**（底图颠倒那次是同一类坑，所以专门测了）
- [ ] 可放置文字标注并直接输入；已放置的文字双击可再次编辑（人工）
- [ ] 文字工具下的「文字 / 序号」预设切换与起始值步进（人工）
- [ ] 画笔绘制跟手无延迟（人工：拖拽时看不出滞后）

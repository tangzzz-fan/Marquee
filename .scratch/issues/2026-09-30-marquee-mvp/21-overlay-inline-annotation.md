# 21: 覆盖层内直接标注（垂直打穿一个工具）

**What to build:** 在覆盖层上直接画标注。先把**矩形**一个工具打穿全链路：
工具栏选中矩形 → 在选区内拖出矩形（实时预览）→ `✓ 完成` → 图里带着这个矩形。
其余工具留给 22。

**Blocked by:** 20

**Status:** ready-for-agent

## 关键设计：绘制与导出**共用同一套 CG 代码**

这是本票最重要的一个决定，也是最容易做错的地方。

- 导出走 `AnnotationRasterizer`（CoreGraphics）
- 覆盖层也是 CoreGraphics（`SelectionOverlayView.draw(_:)` 用 `NSGraphicsContext.cgContext`）

所以**抽出一个共用的 `AnnotationDrawing`**，两边都调它。

于是"覆盖层里看到的"与"导出的"**天然一致** —— 这与 ticket 08 里
"编辑器与导出共用 `AnnotationText`"是同一条思路：各画各的，必然出现
"编辑器里放得下、导出被裁掉半个字"这类**只有把两份输出摆在一起比才能发现**的偏差。

> ❌ **反面做法**：覆盖层用 `NSBezierPath` 自己再画一遍。
> 描边宽度、颜色空间、文字基线都会与导出漂移，而且每次只在**某些图上**看得出来
> （纯色测试图、对称图都是盲的 —— 见 PITFALLS 40）。

## 会话直接复用，不要另写一套

`AnnotationEditorSession`（Core，已有 30+ 条测试）**原样拿来用**：
工具切换、选中集合、撤销/重做栈、裁切草稿、文字预设全都在里面。

覆盖层只是换了个宿主，**不要**为它另写会话 —— 那样两套状态必然分叉，
而且新那套没有测试覆盖。

## 事件映射

| 覆盖层已有 | 标注要用的 |
| --- | --- |
| `mouseDown/Dragged/Up` | 起笔 / 拖拽 / 落定（含 4pt 的点击容差，与现有 `dragSlop` 同源） |
| `⌘Z` / `⇧⌘Z` | 已在 `handleOverlayKeyDown` 里，接上即可 |
| `Delete` | 删除选中对象 |
| `⌥` | 落点后归"无阴影"，**不要**再占用 |

坐标：选区内的点要换算到**原图像素**（`CanvasViewport.imagePoint(forView:cropOrigin:)`
已经有现成的换算，直接用）。

## Acceptance criteria

- [ ] 工具栏出现矩形工具；选中后光标变十字
- [ ] 在选区内拖拽 → 矩形**实时跟随**；松开落定
- [ ] `⌘Z` 撤销、`⇧⌘Z` 重做
- [ ] 「完成」→ 导出的图里带着这个矩形
- [ ] **覆盖层所见与导出结果逐像素一致**（这一条是本票的核心，靠共用绘制保证）
- [ ] 标注不会溢出选区（越界部分被裁掉）
- [ ] 共用绘制有测试：同一份 document + 同一张源图，
      `AnnotationDrawing` 的输出与 `AnnotationRasterizer` 的输出**逐像素相同**
- [ ] 拖拽期间选区几何编辑（若有）与画标注不打架

## 风险

- **性能**：覆盖层每次 `draw` 都会重画标注。标注数量少（个位数）时无碍，
  但如果用户画了几十个，需要按 `PITFALLS` 里"谁改谁推"的做法只重画脏区。
  本票先不做优化，但要在 `draw` 里留一句注释说明这是已知的下一步。
- **与放大镜的叠加顺序**：放大镜画在最上层（`drawMagnifier`），标注要画在它**下面**。

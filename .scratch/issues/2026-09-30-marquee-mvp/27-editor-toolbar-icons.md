# 27 · 编辑器工具栏：把"直接用文字"的按钮换成图标

**状态**: ✅ **已完成**（2026-10-02）
**阻塞于**: 22（尺寸三档按工具换含义）
**来源**: 用户的原话 —— 「格式 使用 icon 代替，现在直接用文字，比较突兀」

---

## 1. 现象

编辑器（长截图那条路进入）的工具栏上，二十来个控件全是图标，中间夹着三处**直接用文字**：

| 位置 | 原来长什么样 |
| --- | --- |
| 文字的两个预设 | 两个汉字按钮：**「文字」「序号」** |
| 序号档的起始值 | 一行文字 **「起始 3」** |
| 三档尺寸 | 三格数字：**「2」「4」「8」** |

在一条纯图标的工具栏里，这三处就是用户说的"比较突兀"。

## 2. 做法

### 2.1 两个预设 → 图标

| 预设 | 图标 | 为什么是它 |
| --- | --- | --- |
| 普通文字 | `textformat.abc` | 带下划线的 "abc"，一眼是"普通文本"；用 `textformat` 会和左边的**文字工具**撞脸 |
| 序号 | `list.number` | 编号列表 |

名称改挂 `.help()`：鼠标停一下就能看到，文案目录里的「文字」「序号」两条 key 也仍然有用
（没有变成孤儿 —— 扫描测试会盯着这一点）。

### 2.2 序号档的起始值 → 小图标 + 数字

「起始 3」→ `#` 图标 + `3`。数字本身是**内容**（它就是当前值），该是数字；
被换掉的是"起始"那两个汉字。

⚠️ 这一改会让 `起始 %lld` 这条 key 变成孤儿 —— 扫描测试当场逮住了
（`catalog 里没有源码找不到的孤儿 key` 变红），随后从翻译表与 catalog 里一并删除：
**188 → 187 条**。

### 2.3 三档尺寸 → 图形，且与覆盖层**同源**

新增 `MarqueeCore/SizeSwatchGeometry.swift`：形状 + 大小只有一份规则，
覆盖层（`drawSizeSwatch`，CoreGraphics）与编辑器（`sizeSwatch`，SwiftUI）都调它。

| 这三档代表 | 画成 |
| --- | --- |
| 线宽 | 由小到大的**圆点** |
| 打码强度 | 由小到大的**方块** |
| 字号 | 由小到大的**字母 A** |

**顺手修掉一个真缺陷**：原来大小是 `4 + value * 1.4` 再夹到上限。
打码那三档是 4/8/16，算出来 **9.6 / 15.2 / 16** —— 后两档差 0.8 点，
在 20 点的格子里根本看不出来。用户点"最强"却毫无变化，只会以为没生效。
现在按**档位序号**均分（0.36 / 0.61 / 0.86），与数值彻底解耦。

精确数值仍在 `.help()` 里（如「线宽 4」），要数字的人鼠标停一下就有。

## 3. 测试

`SizeSwatchGeometryTests`，**5 条**：

形状按含义分 · **三档必须一眼分得出**（相邻差 > 0.15 且最大 ≥ 最小 × 2）·
**档位大小不跟数值走**（三组数值范围差一个量级，画出来必须一样）·
比例恒在格子内 · 越界序号按边界夹住。

变异 3 次全部变红：

| 变异 | 结果 |
| --- | --- |
| 三档差距缩到 0.05（＝复现旧实现"后两档看不出区别"） | ✘ 9 条 issue |
| 字号档也画成圆点 | ✘ 3 条 |
| 去掉序号越界夹取 | ✘ 4 条 |

## 4. 一个靠探针才躲过去的坑

挑图标时 `text.number` **不存在**。`NSImage(systemSymbolName:)` 对不存在的名字返回 `nil`，
`Image(systemName:)` 画出来是**一片空白** —— 不报错、不警告。
所以先跑了个探针把候选名逐个验一遍（和 ticket 17b 探格式说明符同一套办法），
最后用的是 `textformat.abc` 与 `list.number`。记进 PITFALLS 112。

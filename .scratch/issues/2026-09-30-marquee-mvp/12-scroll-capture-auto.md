# 12: 滚动截屏完整版（自动滚动）

**What to build:** 手动滚动已经能用之后，把它升级为"点一下自己滚完"：Marquee 自己发送滚动事件，逐帧抓取并拼接，滚到底自动停下，用户只需要等着看图。同时处理真实世界的脏情况：吸顶标题栏、滚动惯性还没停、页面里有动图或视频。

**Blocked by:** 11

**Status:** 🟡 自动滚动已实现（2026-10-01），真实场景项待人工验收

## 设计约束（已定）

- 自动滚动靠合成滚轮/翻页事件驱动，必须有**停止条件**和**超时保护**（不能让页面无限滚下去）
- 抓帧前要等待滚动停止（停滚检测），否则会拍到运动模糊的帧
- 吸顶元素（sticky header）与动态内容要么被识别并排除，要么让用户框定"只截这个区域"
- 单次自动滚动必须有可中断方式（`Esc` 随时停）

## 实现记录（2026-10-01）

### 入口：覆盖层里的**空格**，不是菜单项

菜单栏已经 6 项（PRD 3.1 的上限），再加就得先合并。而自动滚动只在"长截图进行中"有意义 ——
挂在那个状态自己的提示行里，比多一个大部分时候点不动的菜单项更合理。

- 拖出区域 / 点窗口 → 照旧立刻开始抓帧（**手动模式，行为完全没变**）
- `空格` → 开始自动滚动；再按一次（或 `Esc`）→ 停止，回到手动
- `Esc`（不在自动滚动时）→ 取消整次长截图（与 ticket 11 一致）
- `⏎` / `⌘S` → 结束并出图（两种模式通用）

### ⚠️ 自动滚动是本项目**唯一**需要「辅助功能」授权的功能

手动滚动是用户自己在滚，Marquee 一个事件都不用发；自动滚动必须**代用户发滚轮事件**，
而 macOS 把"向其它进程注入事件"划进辅助功能授权（`CGPreflightPostEventAccess` /
`CGRequestPostEventAccess`，`CoreGraphics` 里，**头文件没有声明但符号存在**）。

因此它是**按需**的：只有用户真的按了空格才问一次；拒绝了只是退回手动，
而截图、标注、手动长截图**都不需要**这个权限，一行都不受影响。

### 代码落点

| 关注点 | 落在哪 | 为什么 |
| --- | --- | --- |
| 什么时候滚/等/收工 | `MarqueeCore.AutoScrollDriver` + `AutoScrollPolicy` | 纯编排，可脱机单测（12 个用例） |
| 合成滚轮事件 | `MarqueeCapture.CGEventScrollWheelEmitter` | CGEvent 是系统 API |
| 授权探测 | `MarqueeCapture.SystemPostEventPermission` | 同上；"问过一次"只记进程内，不写 UserDefaults |
| "画面停没停" | `ScrollCaptureSession.probeFrame()` | **只配准、不入图**，不动任何会话状态 |
| 节奏循环 | `SelectionOverlayController.runAutoScrollLoop` | 与手动模式同一种"被宿主逐拍驱动"的写法 |

### 几个刻意的决定

- **先等停稳再抓帧**：探测帧用 `probeFrame()`，它不改 `frames` / `stitcher` / 静止计数 ——
  否则"多看了两眼"会把会话的判定带偏（比如把静止计数推到"到底"）。
- **"到底"看长图高度有没有增长**，而不是复用会话的 `atBottom` 提示：
  连续两步没有新内容才算到底（一步就判死会把"加载中的空档"误当到底）。
- **事件先对准指针**：滚轮事件是按**指针下方的窗口**派发的，指针不在选区上就滚了别的窗口
  （用户看到的是"什么都没发生"）。所以 `begin(targeting:)` 先把指针挪到选区中心。
- **拆成一串小事件**：单个巨大的滚轮事件有的应用当翻页跳到底、有的被惯性抹平。
- **符号**：CGEvent 的 `wheel1` **向下滚是负值**（与 `NSEvent.scrollingDeltaY` 一致），
  写反了不会报错，只是方向相反。
- **`Esc` 在自动滚动中只停滚动，不丢会话**：画面与已拼部分都留着，用户接着自己滚或按 `⏎` 结束。

## Acceptance criteria

- [x] 选中区域后一键启动自动滚动，页面自动滚动到底后停止并给出长图（`空格`；到底/到上限/步数熔断都自动交图）
- [x] 滚动过程中 `Esc` 可立即中断，已拼接部分保留可用（只停自动滚动，会话留着）
- [ ] 页面含吸顶标题栏时，最终长图中标题栏**只出现一次**或按预期处理，不重复堆叠
      —— 拼接器的「长图第 y 行归**最早**那一帧」已内建一份免费的抗吸顶收益，**真实页面未验**
- [ ] 页面含视频/动图时，不产生明显鬼影；若无法避免则给出提示 —— **未处理**
- [x] 惯性未停即抓帧的情况被规避（有停滚检测），无运动模糊
- [x] 已滚到底的页面能正确检测并停止，不产生无限循环
- [x] 超时保护生效：异常页面（如无限加载）不会让应用卡死（单步等待上限 + 步数熔断 + 采不到画面的熔断）
- [x] 手动滚动模式仍然保留可用（作为自动滚动失败时的兜底）

## 人工验收补充（在 §G 的手动清单之外）

1. 先给一次「辅助功能」授权：**系统设置 → 隐私与安全性 → 辅助功能 → 勾选 Marquee**。
   没授权时按空格应当**什么都不发生**，只在提示行说明原因（不会弹到别的应用上乱滚）。
2. 打开一个长页面（浏览器长文 / 聊天记录），`滚动截屏` → 拖出区域 → 按 `空格`。
   预期：页面自己往下滚，提示行显示"自动滚动中 / 已拼 N px"，滚到底后自动出图。
3. 中途按 `空格` 或 `Esc`：应当**立刻停手**，已拼的部分还在，接着自己滚还能继续拼。
4. 含吸顶标题栏的页面：看长图里标题栏有没有堆叠（这一条**没把握**，见上面未勾选项）。
5. 含视频/GIF 的页面：看有没有鬼影（同上）。

## 遗留（下一步要做的）

- 吸顶条的**显式**检测（现在是靠拼接排布顺带缓解，没有专门的判定）
- 动态内容（视频/GIF）造成的鬼影：至少要能识别并提示"这段内容在动，长图里可能有残影"
- `AutoScrollPolicy` 的阈值按真实页面调（滚太快/太慢都在这里）

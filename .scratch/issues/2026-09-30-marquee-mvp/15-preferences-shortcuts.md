# 15: 偏好设置四页与快捷键配置

**What to build:** 一个克制的偏好设置窗口，正好四页：通用（启动行为）、截屏（光标、阴影、延时）、输出（保存位置、格式、模板）、快捷键。快捷键可以自己改，撞车了会明确告诉你和谁冲突。

**Blocked by:** 02, 05

**Status:** 🟡 已实现，待人工验收（2026-10-01）

## 实现记录

### 四页各自有什么

| 页 | 可调项 | 数量 |
| --- | --- | --- |
| 通用 | 截图后播放提示音 / 开机自启 | 2 |
| 截屏 | 截图包含鼠标指针 / 窗口截图带阴影 / 延时截图（0·3·5·10 秒） | 3 |
| 输出 | 保存位置 / 格式 / 质量 / 文件名模板 | 4 |
| 快捷键 | 录制 + 恢复默认 + 冲突提示 | 1 |

（加上"输出"页里那个说明可用变量的提示行，共 10 个可调项 —— 与"每页要克制"的约束相符。）

### 几处刻意的决定

- **没有"确定 / 应用"按钮**：改一下立刻生效、立刻落盘。这类偏好都是一眼能看出效果的小开关，
  而"改完忘了点应用"是这类窗口最经典的坑。
- **延时是"覆盖层出现**之前**"的那几秒**：覆盖层一旦出现就吃掉所有鼠标事件，
  那时候再等几秒用户反而什么都摆不了（要截的往往是"需要先摆出来的东西"）。
  倒计时是个**点穿**的小 HUD，等待期间还能操作下面。
- **`includeCursor` 用闭包注入采集器**（每次抓帧现读），不是属性、也不是每个方法一个参数：
  属性会引入"这次带不带取决于谁最后写的"这种竞态；参数要改十来处调用（漏一处没提示，
  而长截图漏掉的后果是**每一帧都盖一个指针**，拼出来的长图上有好几只手）。
  长截图那条路显式传 `{ false }`。
- **窗口阴影**：偏好给的是**默认值**，覆盖层里按 `⌥` 仍是"临时反过来"（PRD F4），两者相乘。
  写 `!isOptionDown` 会让偏好那一项彻底失效。
- **登录项失败必须说清楚并把开关拨回去**：界面显示"已开启"而系统里没有，
  用户只能靠重启去发现。开发构建（未签名）注册失败是正常现象，提示里点明了。
- **刻意没有"截图后是否自动复制到剪贴板"这一项**：那条链路目前无条件写剪贴板，
  而"能不写"要靠注入空剪贴板 —— 那样 `CaptureOutcome.copiedToClipboard` 这个结果名就成了假话。
  **界面上摆一个兑现不了的开关，比少一个开关糟糕得多。**

### 菜单栏同步调整

- **删掉「延时截屏」占位项** —— 延时已经进了「设置 → 截屏」。同一个功能两个入口，
  用户会以为它们不同步。
- 「快捷键…」改回「设置…」（ticket 02 时它只能改快捷键，所以叫那个名字）。
- 现在是 **5 项**：截屏 / 滚动截屏 / 最近截图 / 设置… / ─ / 退出。

### 验证

`AppPreferencesTests` 8 条 + 原有的快捷键用例。其中两条是"别踩那几个公认的坑"：
**"没存过"必须与"存了 false"区分**（PITFALLS 85）、**非法延时值要被夹回**（存了 999 的话
用户按一下快捷键要等 16 分钟，与"应用卡死"完全一样）。

## Acceptance criteria

## ⚠️ 前情（ticket 02 已提前交付了一部分）

ticket 02 因为"应用启动后要能换快捷键"这条追加需求，已经落地了以下内容，**不要重复造**：

- `MarqueeCore.ShortcutService`：校验 → 试注册 → 成功才落盘 → 冲突回滚
- `MarqueeCore.ShortcutValidation`：修饰键缺失 / 仅 ⇧ / 系统保留组合的拦截
- `MarqueeCore.UserDefaultsShortcutStore` + `MarqueeSettings.CarbonGlobalHotKey`
- 菜单栏「快捷键…」→ `App/ShortcutPreferencesWindowController`（单页，仅快捷键）

因此本条 ticket 的范围调整为：**把那个单页面板并进四页偏好设置窗口**，并把「通用 / 截屏 / 输出」三页补齐。菜单项届时从「快捷键…」改回「设置…」。

## 设计约束（已定）

- **不超过 4 页**，每页可调项要克制（这是"功能简洁"的硬约束）
- 快捷键冲突检测：Carbon 重复注册会返回 `-9878`（`eventHotKeyExistsErr`），据此提示用户
- 偏好必须落盘并立即生效，不需要重启

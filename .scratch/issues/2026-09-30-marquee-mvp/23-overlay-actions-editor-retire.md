# 23: 动作区补齐 + 独立编辑器的去留

**What to build:** 把 OCR、保存落盘、钉图接进覆盖层工具栏的动作区；
并**决定并落实**独立编辑器窗口的去留（含长截图那条特殊路径）。

**Blocked by:** 22

**Status:** ready-for-agent

## 结论先行：编辑器窗口**保留，但只服务长截图**

普通截图在覆盖层里就地标注就够了（20–22 已经把这条路铺平）。
但**长截图不一样**：长图可能有几千像素高，**根本放不进一屏** ——
在覆盖层里标注它，用户既看不到全貌、也没法滚动。

所以：

| 路径 | 收尾方式 |
| --- | --- |
| 普通截图（区域 / 窗口 / 整屏） | **覆盖层内完成，不再打开任何窗口**（用户明确要的） |
| 长截图（`Mode.scrollCapture`） | 结束后打开编辑器窗口（保持现状，理由如上） |

因此编辑器的代码**不删**，但只从长截图路径进入。
`-marqueeDemoEditor` 也保留 —— 它是"编辑器能不能打开"的唯一免权限验证入口
（这次排查"窗口打不开"就靠它二分定位）。

> **待确认**：如果后续希望长截图也走覆盖层，那要在工具栏里做
> "长图预览 + 滚动"（预览窗 + 滚动条 + 标注坐标映射），
> 那是另一个量级的改动，**需要单独开票**，不要塞进本票。

## 动作区要接的三件事

1. **OCR**（ticket 13 已实现，服务与识别器都在）
   - 接进工具栏作为**动作**，不占工具位
   - 结果就地呈现（沿用现有的 `TextRecognitionService` 状态机与面板形态）
   - 注意：识别要几百毫秒到几十秒，覆盖层里更要给等待反馈

2. **保存落盘**
   - 复用 `ScreenshotArchiver` + 命名模板 + 序号（`UserDefaultsOutputStore`）
   - 落盘失败必须提示（图已经在剪贴板里，不能装成整次失败）
   - 这一条**编辑器里也要有**（长截图走窗口路径时同样需要）

3. **钉图**（ticket 14，尚未实现）
   - 它是 PRD F7，独立功能，**如果本票范围已经很大就单独开票**

## Acceptance criteria

- [ ] OCR 接进工具栏，识别结果就地呈现，有等待反馈与空结果提示
- [ ] 保存：按输出策略落盘（目录 / 命名模板 / 序号），失败有明确提示
- [ ] 普通截图的路径上**不再出现任何窗口**
- [ ] 长截图的收尾行为与现在一致（仍打开编辑器）
- [ ] `-marqueeDemoEditor` 仍然可用，且其工具栏与覆盖层工具栏**形态一致**
      （共用同一套按钮实现，不要各写一份）
- [ ] 文档同步：`docs/PRD.md`（3.4 编辑器章节）、`docs/STATUS-AND-ACCEPTANCE.md`
      （验收清单里所有「⏎ 确认 → 打开编辑器」的步骤）、`.scratch/.../INDEX.md`

## 风险与顺序

- 本票容易膨胀（三件独立的事 + 一次架构收口）。若开工后发现钉图独立性强，
  **把它拆出去**，不要拖累前两件。
- 收尾顺序建议：**OCR → 保存 → 钉图 → 文档同步**。
  文档放最后是因为前面的形态可能还会微调，先改容易白改。

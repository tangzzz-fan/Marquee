# 10: 放大镜与像素取色

**What to build:** 选区阶段就能看准像素：光标附近显示一块局部放大区域，配合十字线精确定位；同时显示当前像素的色值，按住 `⌥` 可一键复制色值。这样"截得准"和"取个颜色"两件事在同一个动作里完成，不额外占工具位。

**Blocked by:** 03

**Status:** 已实现，待人工验收（2026-10-01）

## 放大镜的可见相位（2026-10-01 修正）

**只在落点之前显示**（`MarqueeCore.SelectionSession.showsMagnifier`）：

| 相位 | 放大镜 | `⌥` |
| --- | --- | --- |
| 悬停（未落点） | **显示**（局部放大 + 十字线 + 中心像素框） | 按住 → 放大镜旁显示 HEX/RGB；**点击 = 复制色值** |
| 拖拽中 | **显示** —— 正在瞄准像素边界 | 按住 → 显示色值（不参与拖拽本身） |
| 已落点 / 已锁定窗口 | **收起** | 恢复 ticket 04 的「无阴影」（落点后 `⌥` 再 `⏎`） |
| 长截图抓帧 | **收起**（像素是滚动前冻结的，已与屏幕无关） | — |

### 为什么改（原先的划分是错的）

初版把 `⌥` 取色放在「已落点、未锁定窗口」，理由是"避开 ticket 04 的 `⌥`＝无阴影"。
**这个理由是错的**：ticket 04 的 `⌥` 是**落点之后**按 `⏎` 时才读的，
悬停相位里 `⌥` 本来就没有任何用途。代价却是把放大镜拖到了落点之后，
与两边都不一致：

- **PRD F4 原话**：「**选区时**显示局部放大与像素级坐标；取色能力并入本项——
  `⌥` **悬停即**在放大镜旁显示 HEX/RGB，一键复制」
- **用户观察（微信截图）**：鼠标经过时放大，**选定区域之后放大镜消失**
- 放大镜的职责是"对准"，不是"看"；选区一确定它就没用了，留着只会挡住刚框定的内容

修法：相位策略抽成 `SelectionSession.showsMagnifier`（`!isSettled`）并单测；
取色移到悬停相位。**不带 `⌥` 的点击不受影响**，仍然是"选中这扇窗"。
读色不再"永远挂着"：不按 `⌥` 时放大镜只留一句「按住 ⌥ 取色」提示（否则没人发现这个能力）。

## 实现要点

| 关注点 | 落点 |
| --- | --- |
| 色值与格式 | `MarqueeCore.PixelColor`（HEX / RGB / HSB，整数 0...255） |
| 取样与放大 | `MarqueeCore.PixelSampling`（夹取、读像素、最近邻放大） |
| 跟随判定 | `MarqueeCore.MagnifierTracker`（`idle` / `moved` / `resample` 三态，见下） |
| 尺寸与摆位 | `MarqueeCore.MagnifierLayout`（点→像素换算、边缘避让） |
| 像素来源 | `MarqueeCore.LensFrameProviding` + `CapturerLensProvider`（复用现有采集器） |
| 绘制 | `MarqueeOverlay.SelectionOverlayView`（放大镜压在最上层，十字线 + 中心像素框 + 色值框） |
| 复制 | `ClipboardWriting.writeText`（新增；色值是文本，不该包成 PNG） |

## 关键取舍

- **像素来源是"覆盖层出现后取一屏、冻结着用"**，不是每次移动去采（那是几十毫秒量级，不可能跟手）。
  代价是覆盖层期间画面若自己变了（视频/动画），放大镜显示的是那一刻的静态画面 —— 对取色可接受。
- **最近邻放大**（Core 与视图两处都设 `.none`）：插值会把相邻像素混起来，而用户就是要看清"这一格是什么颜色"。
  有一条测试专门断言"放大后只允许出现源图那两种颜色"，就是钉这个的。
- **只有放大镜在动时只重画它那一小块**：整屏重绘在 5K 屏上是实打实的开销，而验收项要求 120 fps。
- **取样像素没变就不重建小图**：2x 屏上光标走 1 点 = 2 像素，一半的移动事件落在同一个像素里。

## ⚠️ 落地后发现的两个缺陷（2026-10-01 已修）

1. **放大镜不跟随鼠标**。原来的写法把两件事混成了一件 ——
   「取样像素没变」被当成了「什么都不用做」，于是光标动、像素没变时整个更新被跳过，
   **盒子留在原地**（1x 屏上尤其明显，2x 屏上也会间歇性卡住）；
   而且 `updateMagnifier` 只改内部状态、把「推给视图」交给调用方顺手调 `refresh()`，
   而空闲移动走的是 `updateHover`，那里在"悬停窗口没变"时直接 `return` ——
   **落点之后以及悬停在同一个窗口内，压根没有东西会去推**。
   修法：新增 `MagnifierTracker` 把三态判定抽到 Core 并单测；
   推视图改成由放大镜自己负责（`pushMagnifier`），谁改谁推。
2. **「已复制 …」要等下次移动鼠标才出现**。`statusText` 是烘进 presentation 的，
   只调 `refresh()` 推的还是算好的那一份。改为重建 presentation。

顺带：长截图抓帧期间**不再显示放大镜**（像素是滚动前冻结的，滚起来后内容已与屏幕无关）。

3. **放大镜的可见相位选错了**（见上面「放大镜的可见相位」）：初版让它全程显示、
   取色放在落点之后 —— 与 PRD F4 和用户观察到的微信行为都不一致。现已改为只在落点前显示。

## Acceptance criteria

- [x] 取色格式转换（HEX / RGB / HSB）有单元测试，覆盖边界值（00、FF、全黑、全白、纯色三原色、色相回绕）
- [x] 取样中心夹取：保证整个裁剪区落在图内（角落不产生残图）
- [x] 放大用最近邻，输出中**不出现混色**（这条会在改用插值时立刻转红）
- [x] 点 → 采集帧像素的换算有单测（Retina 2x 主屏 + 右侧 1x 副屏，验证减 origin 与乘 scale）
- [x] 放大镜摆位：四角与边中点都落在屏幕内、不盖住取样点、且**贴着**光标（间距约为 gap）
- [x] 像素来源失败时返回 nil 而不抛 —— 放大镜是锦上添花，不能拖垮截屏主流程
- [x] **可见相位**：悬停与拖拽中显示、落点后收起、取消后不显示（`showsMagnifier` 有单测）
- [ ] 选区过程中光标旁出现放大视图，放大区域内像素可辨认（人工）
- [ ] **落点之前都跟随鼠标**：悬停（同一窗口内缓慢移动）与拖拽中 —— 人工，见 §3 J8
- [ ] **落点之后放大镜消失**（区域与窗口都算）—— 人工，见 §3 J9
- [ ] 十字线与中心像素框指示的取样位置与最终选区的像素对应关系准确（人工）
- [ ] 按住 `⌥` 时放大镜旁显示 HEX 与 RGB（不按 `⌥` 时只留「按住 ⌥ 取色」提示）（人工）
- [ ] **悬停时**按住 `⌥` 点击复制，粘贴出来是 `#1A2B3C` 这样可用的文本；
      不带 `⌥` 的点击仍然是"选中这扇窗"（人工）
- [ ] 落点后按 `⌥` 再 `⏎` 仍是"无阴影"，没有被取色抢走（与 ticket 04 不冲突）（人工）
- [ ] 拖拽期间放大镜跟手不掉帧（人工：120 fps；也是 SPIKE M16 的实测项）
- [ ] 屏幕四角位置放大镜自动避让（人工）

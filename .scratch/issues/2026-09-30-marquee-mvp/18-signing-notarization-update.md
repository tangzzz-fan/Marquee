# 18: 打包签名公证与更新机制

**What to build:** 产出一个别人能直接下载安装、双击不会被 Gatekeeper 拦下来的 Marquee。同时具备版本更新能力，让后续版本能推送给已安装的用户。

**Blocked by:** 17

**Status:** ready-for-agent

## 设计约束（已定）

- 走 **Developer ID 公证分发**，**不上 Mac App Store**（沙盒会约束滚动截屏等系统级能力）
- 需要 `com.apple.security.device.audio-input` 等权限时明确列出，但不申请不必要的受限权限
- 首次启动不应有引导弹窗（保持"零弹窗打扰"原则），但权限申请必须是清晰的

## Acceptance criteria

- [ ] 能产出一个归档的安装包（DMG 或 PKG），双击可安装
- [ ] 在**未安装开发环境的另一台 Mac** 上安装后可直接打开，无"无法验证开发者"拦截
- [ ] 首次启动后第一次截屏的权限引导流程正常（跳转系统设置 → 授权 → 可用）
- [ ] 应用图标、名称、版本号在 Finder 与菜单栏中显示正确
- [ ] 版本更新机制可用：能从旧版本检测到新版本并完成更新（或至少给出清晰的手动更新指引）
- [ ] 有构建与发布的操作记录文档（签名 / 公证步骤可复现）
- [ ] 记录最终包体大小与最低系统版本

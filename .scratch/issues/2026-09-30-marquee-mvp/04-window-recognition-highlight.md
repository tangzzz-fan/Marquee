# 04: 窗口识别与悬停高亮

**What to build:** 覆盖层出现后，鼠标移到任意窗口上，那个窗口被完整高亮出边框；单击或 `⏎` 先**落点停住**（不立刻采集），再 `⏎` 截取**这一扇窗**（默认带系统投影，被挡住的部分仍属于该窗，不含叠在上面的其他窗口）。落点后按住 `⌥` 再确认则得到无阴影、无背景的纯净窗口内容。叠在一起的画面请拖选区。这是旧版 Snip 的招牌能力。

**Blocked by:** 03

**Status:** 已实现，待人工验收（2026-10-01）

## 设计约束（已定）

- 窗口清单来自 `SCShareableContent`（`SCWindow` 提供 `windowID` / `frame` / `windowLayer` / `owningApplication` / `isOnScreen` / `isActive`）
- 单击 / `⏎` 高亮窗口：先落点停住，再 `⏎` 才采集独立窗口 + 系统阴影（与拖选区同一套确认）；叠层画面用拖选区
- 落点后按 `⌥` 再 `⏎`：只要这一扇窗，无阴影、无背景
- 需要过滤系统窗口与菜单栏层；命中按**屏幕上的前后顺序**（前台优先），不按 layer 数字把被挡住的窗提前
- 不在在屏窗口列表里的、以及全透明的窗不参与命中，避免选中区域内看不见的窗
- 窗口清单需缓存并在覆盖层期间失效重取，避免每次悬停都查一遍
- `Esc` 一次退出全部屏幕的蒙层（面板默认的 cancel 只会关掉当前这一块）

## 实现要点（落地后回填）

| 关注点 | 落点 |
| --- | --- |
| 窗口值类型 + 筛选/命中 | `MarqueeCore.WindowInfo` / `WindowCatalog`（按在屏前台→后台命中，被挡住的不选） |
| 采集编排 | `MarqueeCore.WindowCaptureFlow`（权限门共用 `CaptureGateRunner`） |
| 窗口清单接缝 | `MarqueeCore.WindowListing`；实现 `ScreenCaptureKitWindowLister` |
| 采集 | 窗口落点后 `⏎` 走 `captureWindow`（带阴影）；`⌥` 再确认＝无阴影独立窗口。叠层＝拖选区 |
| 悬停绘制 | `SelectionOverlayView`：圆角镂空 + 2pt 描边；拖选区时不画悬停；窗口落点后仍画窗口框，等 `⏎` |
| 单击 vs 拖拽 | 松手位移 < 4pt 且命中窗口 → 窗口落点停住；拖过 slop → 选区落点停住 |
| 清单时机 | 覆盖层先出现，清单并行拉取（ticket 03 约束：不要串行等 SCK） |

## Acceptance criteria

### 自动化已验证

- [x] 窗口命中：前台优先；被挡住的窗即使层数更高也不选；只露出的区域才命中后窗；不在屏上的窗丢掉
      —— `WindowCatalogTests`
- [x] 窗口采集流程：独立窗口带阴影 / `⌥` 无阴影；跨屏取最大 scale；权限没过不采集
- [x] 窗口落点：悬停时 `⏎`＝停住不是整屏；锁定后再 `⏎`＝截窗；微调后改走区域
- [x] 全量 `./scripts/test.sh` **128 tests / 24 suites 全绿**

### 待人工验收

- [ ] 鼠标悬停在任意普通窗口上，该窗口边界被高亮，高亮框与窗口实际边缘贴合（含圆角窗口）
- [ ] 单击高亮窗口后选区/高亮**停住**，尚未进剪贴板；再 `⏎` 才得到**这一扇窗**（带系统阴影，不含叠在上面的其他窗口）
- [ ] 悬停窗口时按 `⏎`，同样先停住，而不是立刻整屏或立刻截窗；再 `⏎` 才采集
- [ ] 窗口落点后按住 `⌥` 再 `⏎`，得到无阴影、无背景的窗口内容
- [ ] 两个窗口叠层时，拖选区能截到屏幕上实际看到的叠层；点窗口仍只得到被点中的那一扇
- [ ] 悬停菜单栏、Dock、桌面空白处时不出现误导性高亮
- [ ] 悬停到 Marquee 自己的覆盖层时不把自己当成目标窗口
- [ ] 悬停高亮刷新在 120 fps 下不掉帧（覆盖层重绘实测记录）
- [ ] 拖选区与点窗口互不干扰：拖一下仍是区域、松开停住；点一下是窗口落点，再 `⏎` 才截窗

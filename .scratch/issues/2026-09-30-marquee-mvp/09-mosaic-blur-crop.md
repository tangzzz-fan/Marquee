# 09: 马赛克与毛玻璃模糊 + 裁切

**What to build:** 截图里的敏感信息要能打码：用马赛克或毛玻璃模糊涂抹一块区域，涂抹范围本身也是一个可选中、可移动、可删除、可调强度的对象。另外提供裁切：把截图裁到需要的范围，且裁切可被撤销回原图。

**Blocked by:** 07

**Status:** 已实现，待人工验收（2026-10-01）

## 实现要点

| 关注点 | 落点 |
| --- | --- |
| 打码滤镜 | `MarqueeCore.RedactionFilter`（CoreImage 的 typed filter API：`CIPixellate` / `CIGaussianBlur`） |
| 打码对象 | `AnnotationKind.mosaic` / `.blur`，强度在 `AnnotationStyle.effectStrength`（块边长 / 半径） |
| 导出渲染 | `AnnotationRasterizer.drawRedaction`：抠源图补丁 → 滤镜 → 贴回 |
| 编辑器渲染 | 画布画**同一份**滤镜输出（缓存键 = 框 + 强度 + 类型），所以看到什么导出来就是什么 |
| 裁切模式 | `AnnotationEditorSession.beginCrop / updateCrop / moveCrop / commitCrop / cancelCrop` |

### 三个必须一起想清楚的地方

1. **补丁贴回时要局部反翻 CTM**。当前 CTM 已经是"左上原点、y 向下"，
   而 `draw(image, in:)` 在那种上下文里会把图**上下颠倒**放进去。
   马赛克因为细节被抹掉未必看得出来，模糊会很明显 —— 两条回归专门盯它。
   测试底图必须**不对称**：一开始用"上黑下白各一半"，那种图关于水平中线镜像对称，
   翻转后逐像素相同，**变异测试直接漏网**；换成"顶部一条黑带"才抓住。
2. **打码缓存在 `onChange` 里重算，不能在 `Canvas` 绘制闭包里改状态**（SwiftUI 禁止渲染期间改状态）。
   缓存键含框 / 强度 / 类型，拖框时每帧都会重算一次，但只是拖的那一块。
3. **裁切外的标注保留不动**，只是暂时看不到。删掉再补回来是"两处状态要对齐"，
   而保留原件只有 `cropRect` 一处状态，撤销天然正确。

### 实测

单次打码（400×300 补丁，**预热后**）：**马赛克 0.70 ms、模糊 0.81 ms** —— ticket 目标是 ≤ 5 ms。
冷启动 46 ms（建 `CIContext` + 编译着色器），所以 `CIContext` 是共享常量、且耗时测试先预热。


## 设计约束（已定）

- 模糊与马赛克一律走 **CoreImage**（`CIGaussianBlur` / `CIPixellate`）。实测全画布 2.64 ms，比手工 CG 像素化（15.96 ms）快 6 倍；不要手写 Metal kernel
- 打码对象同样进对象模型，不是"画进位图就完事"——否则无法调整强度或撤销
- 裁切进撤销栈，语义：`⌘Z` 先撤销裁切之后的标注，再撤销裁切本身，撤销裁切要恢复完整原图与原有标注位置

## Acceptance criteria

- [ ] 可用马赛克涂抹区域，涂抹处可辨认地被像素化；可切换为毛玻璃模糊
- [ ] 打码区域可被选中、移动、改变大小、删除、调整强度
- [ ] 打码效果在导出后与编辑器中一致（不能只有预览生效）
- [ ] 裁切可拖框调整，回车应用，`Esc` 取消；裁切后画布尺寸随之改变
- [ ] 裁切后可 `⌘Z` 还原到完整原图，且原有标注位置正确恢复
- [ ] "标注 → 裁切 → 标注 → 撤销三次"的交错撤销语义正确
- [x] 单次打码操作实测 ≤ 5 ms（马赛克 0.70 ms / 模糊 0.81 ms，400×300 补丁、预热后）
- [ ] 裁切与打码对象的几何变换有单元测试（含裁切边界外的标注如何处理）

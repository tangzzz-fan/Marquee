## 1. 切片原则

每条 ticket 是一条**窄而完整**的路径，穿过所有层（采集 / 覆盖层 / 编辑器 / 输出 / 测试），落地即可独立演示。**不做横向切片**（不允许出现"先做完所有权限逻辑"这类票）。

- 无阻塞边 → 可立即开工
- 每条 ticket 的验收标准必须是**可运行验证**的，不是"代码写完"
- 已提前验证的技术结论（见 `docs/SPIKE-PLAN.md`）作为实现约束写进对应 ticket，不再重复验证

## 5. 第二批的切法（为什么要这样拆）

用户要的是「框选后在选区下方出工具栏，**不阻断操作**」。拆成 20–23 而不是一张大票，
分界线是**「一次只让一类问题可能出错」**：

| 票 | 只负责 | 出错时能一眼定位到 |
| --- | --- | --- |
| 20 | 工具栏出现在哪、`⏎` 之后去哪 | 布局 / 收尾分支 |
| 19 | 选区的几何编辑与吸附 | 控制点命中 / 缩放 / 吸附线 |
| 21 | 绘制这条链路（先只打穿形状类四个工具） | 事件 → 会话 → 绘制 → 导出 |
| 22 | 剩下三类工具（它们的前提各不相同：文字要输入框、打码要底图） | 各工具自身的前提 |
| 23 | 外围动作（OCR / 保存 / 钉图）+ 架构收口 | 依赖装配 |

两个关键判断写在对应票里，这里只点一句：

1. **21 的核心是"覆盖层与导出共用同一套 CG 绘制"** ——
   这和 ticket 08 里"编辑器与导出共用 `AnnotationText`"同源。
   各画各的，必然出现只有把两份输出摆在一起才能发现的偏差。
2. **23 的结论是"编辑器保留、但只服务长截图"** ——
   长图放不进一屏，在覆盖层里没法标注它。普通截图则彻底不再开窗口。

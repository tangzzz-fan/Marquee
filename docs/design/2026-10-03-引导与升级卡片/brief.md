## 一、这是什么

**Marquee** 是一个 macOS 截图 + 标注工具（原生 AppKit，不是网页、不是手机 App）。

> 按一下快捷键 → 屏幕冻住 → 框出要截的那块 → **就地图标注** → 直接进剪贴板。

它**没有主界面**：装完之后只是菜单栏上的一个图标。用户对"多一步弹窗"极度敏感。

## 二、这一轮只做两块（锁死范围）

1. **首次启动引导页**（Onboarding）
2. **升级卡片**（Pro upgrade card）—— 它有两种载体，都要

**明确不做**：覆盖层工具条、编辑器、偏好设置、最近截图面板。
不要顺手改它们的风格，也不要输出它们的稿子。

两块必须**共用一套视觉语言** —— 它们本来就是"同一个产品跟用户说话的两种场合"。

## 三、第一块：首次启动引导页

### 它出现在什么时候

用户第一次打开 app。此时菜单栏图标**已经在**，快捷键**已经能用**。

### 现在长什么样（纯功能先跑通，视觉没设计过）

macOS 原生窗口，**440 × 336 点**，一页说完，右下角只有一个按钮：

```
┌─ 欢迎使用 Marquee ──────────────────────┐
│                                         │
│  Marquee 就在菜单栏                       │  ← 21pt semibold
│  按一下快捷键，屏幕冻住，框出要截的地方。      │  ← 13pt 次要色
│  截图 · 标注 · 滚动截屏 · 识别文字 · 钉图    │  ← 12pt 更淡
│                                         │
│  截屏快捷键    [ ⌃Q ]                    │  ← 标签 + 220×34 的录制框
│                                         │
│  屏幕录制：还没授权         [打开系统设置]   │  ← 状态文字 + 按钮
│                              [ 开始使用 ] │
└─────────────────────────────────────────┘
```

- 快捷键那个框是**可点的录制控件**：点一下变"按下新的组合…"，
  然后用户按什么就录什么（这是这一页**唯一有交互**的地方）
- 权限那行：**已授权时按钮会消失**，只留「屏幕录制：已授权」

### 它要给人什么印象

**"这东西很轻、很快"** —— 而不是"又一个要我读完的欢迎页"。

现在的版本信息层级比较平：三行文字字号递减，但**没有真正的视觉重点**；
标题、快捷键框、权限行、按钮四块的间距也看不出关系。

### 请你决定的事

- 这一页的**视觉主角是谁**？我以为是那个快捷键录制框（因为它是唯一能动手的地方），
  但现在它和权限行看起来同等重要
- 那三行文字（标题 / 副标题 / 名词行）要不要压成两行甚至一行半？
  **我倾向于更少**，但怕新用户看不懂这个 app 是什么
- 权限那行在"还没授权"时是个**需要用户行动**的状态，它该有多显眼？
  太显眼会觉得被胁迫，太弱会直接滑过去

## 四、第二块：升级卡片

### 它为什么存在

免费版有 4 项 Pro 能力（长截图 / 识别文字 / 钉图 / 最近截图不设上限）。
用户在免费版点这些入口时，**不能静默失败**，也不能弹一个"购买"的账单页 ——
要先解释清楚，并且**不打断他手上这次截图**。

### 载体 A：覆盖层内原地弹的小卡片

用户在覆盖层里点了「识别文字」或「钉图」，卡片**原地**弹在工具条旁边：

```
300 × 140 点
标题（如「识别文字是 Pro 能力」）+ 一行正文 + 两个按钮
按钮示例： [了解 Pro]  [7 天免费试用]
```

**关键约束**：卡片开着时按 `Esc` **只收卡片**，用户拍下的屏幕、已经框好的选区、
已经画好的标注**一字不动** —— 他还能接着把这次截图做完。

### 载体 B：菜单入口旁的小面板

用户在菜单栏点了「滚动截屏」（也是 Pro 能力）时，**覆盖层还没出现**，
所以卡片画不到覆盖层上，只能是个独立小面板：

- **不抢键盘焦点**（抢了会让覆盖层失去 key，键盘就失效了）
- 点别处或按 `Esc` 自己收起来
- 贴在鼠标下方

### 文案有三种情形（内容不用你写，但**结构要能容纳**）

| 情形 | 主按钮 | 次按钮 |
| --- | --- | --- |
| 从未购买、还能试用 | 7 天免费试用 | 了解 Pro |
| 试用已结束 | 了解 Pro | 恢复购买 |
| 购买被撤销 | **恢复购买** | 了解 Pro |

### 请你决定的事

- 这是**广告**还是**说明**？我倾向后者 —— 它出现在用户"正想干一件事"的时刻，
  任何推销腔都会让人烦。但"了解 Pro / 7 天免费试用"两个按钮毕竟是在卖东西
- 两个按钮怎么排主次才不会像广告弹窗？现在是用色块区分，
  但我不确定在**覆盖层的深色材质上**够不够清楚
- 载体 A 是深色（在覆盖层里），载体 B 是系统面板 —— **两者要不要长得一样？**
  我倾向一样（同一个东西的两副面孔），但它们各自的环境差很多

## 五、必须遵守的硬约束

| # | 约束 | 为什么 |
| - | --- | --- |
| 1 | 引导页窗口**尺寸可以调整**（我不绑死 440×336），但**不能变成一个要分页的多步流程** | 今天刚从三步合并成一页，分页那套已经删了 |
| 2 | 升级卡片**不允许要求新弹窗/新页面** | 产品的全部价值就在"少一步" |
| 3 | 引导页与卡片**共用同一套视觉语言** | 否则它们看起来像两个 app 的东西 |
| 4 | 深色优先，但**引导页要两种外观都给**（它是普通窗口） | 覆盖层里那张卡片只需深色 |

> ⚠️ 约束 1 与 2 是产品决策。如果你认为必须打破才能做出好体验，
> **单独提出来说明理由**，我会评估；但不要默认它们可以动。

## 六、请交付什么

1. **引导页**：深色 + 浅色两套静态稿，含尺寸标注
2. **升级卡片**：载体 A（深色，在覆盖层材质上）与载体 B（系统面板）两种，
   含尺寸标注
3. **差异态**：按钮的默认 / 悬停 / 按下；引导页权限行的"未授权 / 已授权"两态；
   卡片的三种文案结构
4. **先给结构、再给像素**：我最需要的是"为什么主角是它、为什么这三行字该这么排"，
   而不是一张更好看的图
5. 对齐 **macOS 原生观感**（不是网页、不是移动端）

## 七、不用做的事

- 不用写正式文案（中文文案我自己写，稿子里用示意文字即可）
- 不用做交互动效说明（我按尺寸还原，动效另说）
- 不用管深色/浅色的自动切换逻辑，两套稿子都给就行

### 1.3 当前可用形态（能直接演示的）

- 按 `⌃Q`（或菜单「截屏」）→ 逐屏覆盖层 → 拖选区 / 点窗口 / 双击整屏 → 停住 → `⏎` 提交

### B. 已知的未验证高风险项（不影响开工，但影响"能不能交付"）

| # | 项 | 为什么是风险 |
| --- | --- | --- |
| B1 | **应用未激活时覆盖层的键盘是否生效** | 面板用 `.nonactivatingPanel`（不抢焦点是刻意的），但 `Esc`/`⏎`/方向键能否收到没验过。**这是覆盖层最没把握的一条** |
| B2 | **滚动截屏抓帧期间面板失焦后 `⏎`/`Esc` 失效** | 抓帧要鼠标穿透，用户去点了别的应用就可能丢 key 焦点。无解则需全局键盘监听 —— 但那要输入监控权限，与"不申请多余权限"冲突 |
| B3 | **真实滚动场景** | sticky header / 惯性未停即抓帧 / 页面内有视频动图。合成数据覆盖不到，SPIKE 标为 M13–M15 |
| B4 | **超长图在编辑器里的渲染** | SPIKE E5 标为风险项：Canvas 可能按需光栅化整幅。1200×9000 级别需实测 |
| B5 | **耗时预算无实测记录** | "按下快捷键 → 剪贴板可用 ≤ 150 ms"目前只有日志埋点，没有真实数字 |
| B6 | **混合 DPI / 多显示器** | 需要外接一块非 Retina 屏才能验（SPIKE M5） |

### C. 环境限制（不影响你，只影响我这边）

我这侧的 shell 被沙箱包裹，`swift-plugin-server` 启动时自己再套一层沙箱会被 SIGKILL，
于是 `xcodebuild` 报 SwiftUI 宏 `produced malformed response`。
**判别方法**：`./scripts/test.sh`（走 SwiftPM）能过、`./scripts/build.sh` 不能 → 一定是宿主沙箱在挡，别动代码。
我这边的替代验证：App 层用 `swiftc -typecheck -I Modules/.build/out/Products/Debug App/Sources/*.swift`（已过）。
详见 `docs/DEV-NOTES.md` 第 4.1 节。

## 3. 人工验收方案

### 0. 一次性准备

```bash
cd /Users/tango/Developments/Marquee
./scripts/build.sh          # 产物固定在 <repo>/DerivedData/Build/Products/Debug/Marquee.app
```

| 检查 | 命令 / 动作 | 期望 |
| --- | --- | --- |
| 签名稳定 | `codesign -dvvv DerivedData/Build/Products/Debug/Marquee.app \| grep -E "Authority\|flags="` | `Authority=Apple Development…`、`flags=0x0`（**不是** `adhoc`） |
| 清掉历史授权条目 | `tccutil reset ScreenCapture dev.tango.Marquee` | 会清掉所有 Marquee 授权记录，之后需重新勾选一次（只做一次） |
| 状态一页纸 | `DerivedData/Build/Products/Debug/Marquee.app/Contents/MacOS/Marquee -marqueeDiagnostics` | 权限状态 / preflight 原始值 / 当前快捷键 / 注册结果 / 构建签名身份 |

> `-marqueeRequestPermission` 可单独触发"登记进「屏幕录制」列表 + 请求授权"，不必等按快捷键。

DerivedData/Build/Products/Debug/Marquee.app/Contents/MacOS/Marquee -marqueeDiagnostics

# 单独触发"登记进屏幕录制列表 + 请求授权"
... -marqueeRequestPermission

# 覆盖层 / 编辑器的开发冒烟（1.5 秒自动退出，验证创建→绘制→拆解不崩）
... -marqueeSmokeOverlay
... -marqueeSmokeEditor

# 截图耗时与落盘结果
log show --last 5m --predicate 'subsystem == "dev.tango.Marquee"' --style compact

### 起因（用户提出，我上一版结论下重了）

我原先推荐"bundle id 不变、靠数据目录隔离"。用户指出 **iOS 常规做法就是两个 id**，
并说 `dev.tango.Marquee` 里带 `dev` 不好。两点都对：

- `dev` 既是**前缀**、又正好是**开发版后缀**的自然位置，两者叠一起根本分不清；
- 两个 id **比我那套隔离得更彻底、代码更少**：偏好由系统按 id 自动分域
  （我那套要自己搞 suite 名，而那正是我标为"最容易做漏"的一处），TCC 各自一条。

我原先的反对理由是"开发版测不到真实沙盒交易" —— **前半句对，结论下重了**：
代价不是"放弃支付测试"，而是"沙盒验证放在正式 id 的构建上做"，而那个构建本来就要出。

### 时间窗（Apple 原文）

《Changing the bundle identifier》：「一旦往 App Store Connect 上传过构建，bundle ID 就不能再改」；
"已建 app 记录、**还没上传**构建"时仍可改。DTS Quinn：改了 id **就是新 app**。
另：**删掉 app 记录不释放那个 id**。我们没上传过任何构建 ⇒ **现在改免费**。

### 追问：`Dev` 与 `Debug` 有什么区别？

逐项对比生成工程里的 `XCBuildConfiguration`：**48 项相同、11 项不同，且那 11 项全是编译器设置**。

- **身份上毫无区别**：两者都是 `com.tango.Marquee.dev` ⇒ 数据目录、偏好域、TCC 授权同一份。
  **从 Debug 切到 Dev 不会多出一个身份。**
- 差别只在：`-Onone` vs `-O`、`wholemodule`、`dwarf` vs `dwarf-with-dsym`、
  `ENABLE_TESTABILITY`、`ONLY_ACTIVE_ARCH`、`SWIFT_ACTIVE_COMPILATION_CONDITIONS=DEBUG`、
  `MTL_ENABLE_DEBUG_INFO`、`ENABLE_NS_ASSERTIONS`。
- scheme 各 action：Run→**Dev**、Test→Debug（**工程里没有 test target，空转**）、
  Analyze→Debug、Profile/Archive→Release。
- ⇒ **本项目里 `Debug` 的唯一真实用途**是"要能用的断点"时把 Run 临时切过去。

两条硬规则（已写进文档）：
1. **测性能只能用 Dev/Release** —— `-Onone` 下的数字没参考价值，在 Debug 下觉得卡不代表产品卡；
2. **断言只在 Debug 与 `swift test` 下真的会触发** —— Swift 的 `assert` 由优化级别决定，
   `-O` 会移除它。`ENABLE_NS_ASSERTIONS` 管的是 ObjC 的 `NSAssert`（本项目没用）。

顺带纠正一处：我原先在 `project.yml` 里写的注释「Debug 只用于跑测试」**不准确** ——
测试走 SwiftPM，scheme 的 Test action 是空转。已改成上面那条准确说法。
另外 `SWIFT_ACTIVE_COMPILATION_CONDITIONS = DEBUG` 在本项目**一处都没用到**（全仓 0 处 `#if DEBUG`），
所以不要用它区分开发/正式行为 —— 用 `AppIdentity.isDevelopmentBuild`。

### ⚠️ 查证 StoreKit 之后改掉两处（其中一处推翻了我 ticket 30 的模型）

1. **`RevocationReason` 三档 → 两档。** StoreKit 2 的 `Transaction.revocationReason` 只有
   `.developerIssue` / `.other`；Apple 的 Server Notifications 文档明确写「家人共享的撤销原因
   值就是 **0**（other）」。⇒ **退款与"被移出家人共享"运行时区分不出来** ——
   原来那三档里有两档是**假装能分**，代价是给用户一句很确定但可能错的话。
   现在：`.storeRevoked` / `.purchaseNotFound`。
2. **`currentEntitlements` 已排除已撤销的购买** ⇒ 只看它分不清"从没有过"与"有过被撤"。
   要捞历史得用 `Transaction.all`。

### 三条硬规则（测试钉住）

1. **未校验的交易一律不算数**（`unverified` 可伪造，不能宽容当通过）。
2. **撤销可以被撤销**（Apple 原文：退款撤回后撤销字段被移除、访问要恢复）⇒
   **不许把"曾经被撤销"记成永久状态**，每次从当前事实重算。为此专门写了 `revocationIsReversible`。
3. **「商店里没有」只有在真的问过之后才算证据** —— 查询失败时 `records` 也是空数组，
   照它判会把付过费的人在**断网时锁在外面**。映射函数的文档里写成硬前提，失败路径不进映射。

### 为什么缓存**输入**而不是判定结果

判定规则还会改（这一票就改了一次 `RevocationReason`）。存结果就得指望"用户下次联网被刷新到"，
而有人可能半年不联网。存事实则规则怎么改都能重算。

### 两次自纠（→ PITFALLS 128/129）

1. **手写 JSON 夹具漏了非可选的 `hasUsedTrial`** ⇒ 解码失败 ⇒ `load()` 返回 nil ⇒
   下游 `#expect(loaded?.revocation == nil)` 对 nil 求 `?.` **空跑通过**。
   我的探针也漏了这个字段，所以"验证成功"——探针与被测对象不一致时，它什么都没证明。
   修法：夹具带齐非可选字段 + **先断言"确实读出来了"再断言内容**。
2. **接缝的两个实现分叉**：落盘实现拒绝缓存「还没查」，内存实现无条件覆盖。
   是"两个实现行为一致"那条测试抓住的 —— 各自测各自永远不会发现分叉。

### ① 我这边跑不了 xcodebuild —— 根因找到并解决

**根因**：日志里在宏报错**之前**还有一行 `sandbox-exec: sandbox_apply: Operation not permitted`

**有效解**：`xcrun swiftc -help-hidden | grep sandbox` → `-disable-sandbox`
（"Disable using the sandbox when executing subprocesses"）。
`OTHER_SWIFT_FLAGS=-disable-sandbox` → **BUILD SUCCEEDED**（1分5秒，含签名核验：
`Apple Development: zhenzhi Tang` / `Dev` / `com.tango.Marquee.dev`）。

已固化进 `scripts/build.sh`：`MARQUEE_DISABLE_COMPILER_SANDBOX=1`，**默认不开**
（那层沙箱是真实隔离）。DEV-NOTES 4.1 与 PITFALLS 137 都改了。

**⇒ 从此我可以自己跑完整构建并验证**，不用每次请你代跑。

### ② `Products.storekit` 红色 / 未选中 —— 不是路径错，是文件不在工程里

`storeKitConfiguration:` 只往 scheme 写了个**路径字符串**，不会把文件加进工程；
而 Xcode 那个下拉框列的是**工程已知的 `.storekit` 文件**。
实测那一版 `pbxproj` 里 `Products.storekit` **出现 0 次**。

**修法**：`project.yml` 的 sources 显式声明 + `buildPhase: none`（只做文件引用）。
生成后 `pbxproj` 里已有它（`path = Products.storekit`）。

**路径前缀保持默认 `../../`**：查了官方文档 —— 默认值「suitable for **non-workspace**
projects」，workspace 才用 `"../"`；而本项目实测是**非 workspace 形态**
（scheme 只有一份、在 `.xcodeproj` 里，`.xcworkspace` 下没有 schemes 目录）。

### 新踩到的三条（已写进 PITFALLS 89–92）

1. AppKit 的绘制顺序是「自己的 `draw` → 子视图」，**子视图永远盖在父视图自己画的东西之上**。
   想给自绘区域换材质背景，必须把内容挪到与背景**并列**的兄弟层，不能挂在背景下面。
2. `NSVisualEffectView` / `NSGlassEffectView` **默认参与命中测试**，会吃掉鼠标事件
   （表现与「入口没接线」一样）。要包一层 `hitTest == nil` 的容器。
3. 悬浮面板必须 `.behindWindow`：`.withinWindow` 会拿**变暗蒙层**当素材，糊出来还是一片纯色。

## ticket 26：覆盖层的鼠标光标 —— 完成

用户原话：「需要调整鼠标箭头，目前都是十字」。

### 根因

`SelectionOverlayView.resetCursorRects()` 里一条 `addCursorRect(bounds, cursor: .crosshair)` ——
**整块屏一个十字**，只有选区那 8 个控制点靠"后加的赢"压在上面。
于是工具条按钮、已有标注、选区内部全被那层十字盖住（工具条是 ticket 20 之后才加的，加进去就一直是十字）。

### 做法

- **规则抽进 Core**：`Modules/Sources/MarqueeCore/OverlayCursor.swift`（新）——
  `OverlayCursorKind`（arrow / crosshair / pointingHand / openHand / closedHand / iBeam / resize(handle)）
  + `OverlayCursorContext` + `OverlayCursor.kind(at:in:)` / `kind(for drag:)`。
  分派顺序与 `mouseDown` **一致**，否则会出现"手型压在按钮上、点下去却在重画选区"。
- **光标改成"按点问规则"**，删掉 `resetCursorRects`：
  cursor rect 只能表达矩形，而"压着某个标注"要按**形状**判（斜箭头包围盒里大半是空白）。
  近似成包围盒 = "箭头旁边的空白也伸出可拖的手，点下去什么都没选中" —— 比不做还糟。
- 视图在**三处**各问一次：`mouseMoved` / **`mouseDragged`**（拖拽期没有 mouseMoved）/ 
  presentation 变化时用 `NSEvent.mouseLocation` 补一次（控制点与工具条都是"鼠标停着不动"时出现的）。
- 多屏：设之前先判"自己这块屏的 bounds 是否包含该点"，否则变成**最后刷新的那块屏说了算**。
- 同一光标值不重复 `set()`（每帧重设会闪）。
- 上下文在控制层 `cursorContext(for:)` 里装配（几何全算好），`presentation.cursor` 推给视图。
  要传"正在拼的那一版"进去 —— 它在 `refresh()` 里是局部变量，读属性会拿到上一帧几何。
- 新增 `OverlayAnnotationSession.resizingHandle`（拖标注控制点时显示对应方向的箭头）。

## ticket 28：工具条图标的三处错误（用户贴运行截图报障）—— 完成

### 先对着截图把格子认出来（不猜）

### ① 表情格是实心圆点 —— 多色符号被整片填充

`NSImage.SymbolConfiguration(paletteColors:)` 会把符号**第一层**刷成那个颜色；
`face.smiling` 首选多色渲染、第一层就是整张脸 → **一个实心蓝圆点**。
修法：配置加 `.applying(.preferringMonochrome())`。
逐格对比过 10 个图标：除 `face.smiling` 外完全一样，所以单调着色是意图不是降级。

### ② 文字格是「格式」两个字 —— SF Symbol 自动本地化

`textformat` 有**中文本地化变体**，中文环境下系统自动换成 `textformat.zh`，
而那个变体渲染出来就是**两个字「格式」**。名字一个字都没错。
修法：文字工具改用 **`t.square`**（两语言下都是"方框里的 T"，也正好是参考图那格）。
覆盖层与编辑器都换。编辑器两个预设：`textformat.abc`（→甲乙丙）改 `text.alignleft`，
`list.number` 保留。

**顺手发现**：`text.viewfinder`（识别文字）中文下是「文」在取景框里 —— 这是**预期**，别去改。

### ③ 「样式」跟着表情一起亮 —— 判据写错

原判据 `state.palette != nil`（有弹层就亮），而弹层有两个（样式 / 表情）。
修法：抽进 Core `OverlayToolbarHighlight.isLit(_:activeTool:openPalette:)`，
`.style` 只认 `openPalette == .style`；动作格永不点亮。**6 条测试 + 3 个变异**全红。

### 收尾：catalog 里的 `stale` 是怎么来的

提交前 `git status` 一直显示 `App/Resources/Localizable.xcstrings` 被改 ——
是**用户构建时 Xcode 重写了它**：187 条一条不少、英文翻译一字未改，
但全部被标 `extractionState: stale`（"源码里找不到"）。

**这个标记是错的**：中文字面量几乎都在 **SPM 模块**里，catalog 挂在 **App target** 下，
而 Xcode 的字符串抽取**按 target** 做 —— App 那次抽取看不到模块里的 `L10n.t(...)`。
结论（PITFALLS 116）：① 这个项目**不要用 Xcode 的「Extract Strings」**，
唯一可信的是 `LocalizationScanTests`；② 构建后 catalog 必然脏，
入库形态就按 Xcode 重写后的样子来；③ 核对条数**别数行数**（重排会从 1876 涨到 2063 行），
解析 JSON 数 `strings` 的键。

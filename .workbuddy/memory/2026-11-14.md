# 2026-11-14 · ticket 35：付费 app 转免费 + 内购（老用户权益保留）

## 触发

用户问「iOS 订阅项目要 app 内购买、而不是商店上直接显示要 36 元」→ 澄清是 **macOS**。
查完发现：**IAP 早就上线且在架上卖**，错的是 **app 本体也被设成 ¥36**。

## 现场证据（外部核对，不是台账）

`itunes.apple.com/lookup?bundleId=com.tango.marquee` + 商店页 HTML：

| 字段 | 值 |
| --- | --- |
| 上架 | 已上架 1.1.0（首发 2026-10-27，当前版 2026-11-04） |
| app 本体 | **¥36.00** / 美区 $4.99 · `isFree: false` |
| 内购 | Marquee Pro ¥36.00 · 7 天试用 ¥0.00（都在架上） |

⇒ 用户先付 ¥36 下载，装完发现滚动截屏还带锁，再被要求付 ¥36。

## 决策（用户批准「走方案 A」）

**app 改免费 + 接 `AppTransaction` 认老用户**，分支 `feat/paid-to-free-legacy`。

三条关键设计（都有测试钉住）：

1. **legacy 是独立一位 `legacyPaidPurchaseAt: Date?`，不是 `hasPurchase = true`。**
   塞进 hasPurchase 会让 `StorefrontMapper` 的 `purchaseNotFound` 逻辑把老用户判成**已撤销**
   （老用户的 `Transaction.all` 永远是空的）—— 比不认还糟。
   放**撤销之前**，因为 app 本体的购买与 IAP 的退款是**两笔交易**。
   ⚠️ 这一档的条件**只看 legacy**；写成 `hasPurchase || legacy != nil` 会让内购也压过撤销
   —— 第一版就这么写了，被既有测试当场抓红。
2. **三态，不是两态**：取到且老 / 取到且不是（清掉）/ **取不到（保留已知值）**。
   混成一档，一次断网就永久降级。
3. **版本比较按数值**，不抄 Apple macOS 样例的字符串比较（`"10" < "2"` 为真 ⇒ 10.x 时白送 Pro）。

## 依据（Apple 原文两处）

- macOS 的 `originalAppVersion` = **`CFBundleShortVersionString`**，其它平台才是 build 号；
- 沙盒里它**恒为 `1.0`** ⇒ 沙盒账号一律判成老用户（**这是能在沙盒里验的原因**，不是 bug）。

分界常量 `BusinessModelChange.appVersion = "2.0"`，转免费那一版发 **2.0.0**。

## 验证

- `swift test`：**790 个测试**（基线 750，新增 40），唯一失败是 **`main` 上就存在**的
  `SandboxTests`「记住的是用户选的那一个目录」—— 用独立 worktree 在 main 上复现过，与本票无关。
- **7 个变异全部被抓**：删 legacy 短路（14 条红）· 改字符串比较（3 条）· 失败时清空 legacy（2 条）
  · 缓存字段非可选（解码失败连锁）· 去掉 `canStartTrial` 的 legacy 条件（2 条）
  · 去掉未校验过滤（2 条）· 确认不是时不清除（1 条）。
- **配置一致性守卫**：测试读 `project.yml` 的 `MARKETING_VERSION` 比常量；
  把版本号临时改回 1.1，测试变红并打印「发的是 1.1，判定用的分界是 2.0」。
- **运行期实测**（Dev 产物直接 exec）：
  - 干净缓存 → `权益判定: free`、`app 本体购买: 取不到（noAccount）` —— **判定没被带偏**；
  - 手工写入带 legacy 的缓存 → `权益判定: pro（2025-10-01 购买）`、`能开始试用: 否`、
    `app 本体购买: 取不到` ⇒ **取不到时保留已知 legacy 成立**。
  - 验完已用 `defaults import` 恢复开发版域原值。
- `build.sh` 的 **Dev 与 MAS 两个配置都 BUILD SUCCEEDED**。
